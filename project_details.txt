Our project is called GeoVision. We built it as a local web application for exploring environmental and agricultural data from Paraguay. The starting point is a multi-band GeoTIFF that combines information such as land cover, elevation, soil, climate, satellite observations, and water-related data. Instead of asking the user to open the raster in a GIS program and interpret every layer separately, GeoVision puts the main tasks in one browser interface.

The user starts the Python server, opens the map, and selects an area with two geographic points. The server converts that selection to the raster’s coordinate system and analyzes only the pixels inside it. This is important because the national file is too large for an inefficient, whole-image workflow. The program reads the data in smaller windows, applies the scale and offset stored in the raster, ignores missing values, and returns statistics such as coverage, minimum and maximum values, averages, variation, and class counts. Users can also inspect a single cell, download a selected area as a GeoTIFF, or save the statistics as JSON.

The project also includes a few tools built on top of this analysis. It can create a preliminary map of crop candidates, identify possible restoration areas near mapped water or vegetation corridors, and generate optional soil and water reports. These tools are meant to help users decide what deserves closer attention. They do not pretend that a raster map can replace a soil sample, a field visit, or advice from a local specialist. Keeping that distinction visible was an important part of the design.

The main benefits are accessibility and consistency. A user does not need advanced GIS experience to select an area and obtain a useful first overview. The same processing rules are applied every time, and the output includes warnings when data is missing or incomplete. The intended impact is to make environmental information easier to use in agricultural planning, conservation discussions, and fieldwork preparation. We want the application to help people ask better questions about a place, rather than make unsupported decisions from a single map.

We developed the project mainly in Python. Rasterio handles GeoTIFF files, raster windows, coordinate transformations, reprojection, and exports. NumPy handles arrays and statistical calculations, while SciPy supports some spatial operations. The local API uses Python’s HTTP tools. The interface uses HTML, CSS, and JavaScript for the map, forms, legends, reports, and downloads. Google Earth Engine supports the data-export scripts that prepare the source layers. We used Git and GitHub for version control. The application runs on an ordinary computer with Python, a web browser, and enough disk space for the raster; it does not require specialized hardware.

The creative part of GeoVision is the way it connects these pieces. It is not only a map and not only a statistics script. A user can move from a visual layer to a measured result, then to an optional thematic explanation or a downloadable file. We also separated the optional reports into plugins so they can fail or be disabled without breaking the main map and analysis.

While developing the project, we considered performance, accuracy, usability, privacy, and the risk of overinterpreting the data. We added pixel limits and windowed processing to control memory use. We identify bands from their metadata instead of guessing from their order. The server accepts local requests only, and API keys are kept out of the project files. We also included warnings and limitations in the results so that the software communicates uncertainty instead of hiding it.
