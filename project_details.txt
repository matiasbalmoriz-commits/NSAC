GeoVision is a local geospatial analysis platform designed to make Paraguay’s environmental and agricultural information easier to understand and use. The project combines a multi-band GeoTIFF with a Python backend and an interactive browser interface. Users can visualize land-cover data, inspect individual raster cells, select a geographic area, calculate statistics, generate thematic layers, and export results as JSON or GeoTIFF files.

The system works by receiving two geographic points that define a rectangle. The backend transforms that rectangle into the coordinate system of the source raster, identifies the pixels whose centers are inside the selection, and processes the data in small windows instead of loading the entire country into memory. It reads metadata, applies scale and offset values, ignores NoData values, and produces statistics such as valid pixels, coverage, minimum, maximum, mean, standard deviation, and categorical distributions. Additional modules provide preliminary crop screening, restoration-priority areas, soil profiles, and water indicators.

The project benefits users by bringing several types of geospatial evidence into one accessible workflow. It reduces the need for specialized GIS software, supports reproducible analysis, makes data limitations visible, and allows users to compare conditions across different areas. The intended impact is to support better environmental monitoring, agricultural planning, conservation discussions, and decisions about where field investigation should happen next. The system is designed as decision support: it does not replace field measurements, local knowledge, or professional agronomic and environmental judgment.

The main programming language is Python. The project uses Rasterio for GeoTIFF reading, raster windows, coordinate transformations, reprojection, and exports; NumPy for numerical arrays and statistics; SciPy for spatial operations; and Python’s standard HTTP tools for the local API server. The interface uses HTML, CSS, and JavaScript to display maps, forms, legends, reports, and downloads. Google Earth Engine is used by the data-export scripts to access public environmental datasets such as elevation, land cover, satellite imagery, soil, climate, evapotranspiration, and hydrology. Development and version control use Git and GitHub. The project can run on a normal computer with Python, a web browser, and enough storage for the raster data; it does not require specialized hardware.

The project is creative because it combines data processing, mapping, environmental interpretation, and modular web interaction into one local tool. Instead of presenting a static map, it turns the raster into an exploratory system where the user can move from visual inspection to quantitative analysis, thematic overlays, optional reports, and downloadable evidence. The plugin architecture also allows additional tools to be added without changing the core analysis engine.

During development, the team considered performance, accuracy, usability, data quality, privacy, and ecological responsibility. Windowed processing and pixel limits help control memory and computation. Coordinate validation and metadata-based band identification reduce silent errors. Local-only server rules protect the application from unintended public exposure. API keys are kept out of project files and optional plugins run in isolated processes. The team also considered the danger of overstating raster results, so the system reports warnings and limitations and avoids treating preliminary crop or restoration outputs as automatic prescriptions.
